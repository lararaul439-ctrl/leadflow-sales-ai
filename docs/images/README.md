# Images

**Only one image here is a real capture: `sheet-live-leads.png`, a Google Sheet written by the live n8n Cloud run (see below). All the others are diagrams drawn from the real code or export, or renderings of real command output. None of them is a screenshot of n8n, a terminal or a production system.** Each rendered image carries its own banner saying so, and marks which parts are simulated.

## Rendered evidence (generated by `scripts/render-evidence.js`)

| Image | Content | What is real | What is simulated |
| --- | --- | --- | --- |
| `lead-processing.png` | A fictional lead, the HTTP answer and the redacted text the model receives | Validation, redaction, ids, claim | The sheet is in memory |

| `lead-scoring.png` | Score breakdown, thresholds, caps | Scoring rules | Inputs are the canned signals |

| `follow-up-task.png` | Task and draft pending approval | Task and draft generation | In-memory table |

| `test-suites.png` | Result of each test suite, the build check and lint | Results of the commands at generation time | Suites themselves run against in-memory fakes |
| `security-tests.png` | Titles and results of the security, concurrency and resilience suites | Results | Concurrency is simulated |
| `runtime-verification.png` | The runtime harness locally, and the recorded n8n Cloud result | Local run; the n8n result was recorded during development | n8n execution is no longer inspectable (archived workflow) |

To regenerate them:

```bash
node scripts/render-evidence.js --out /tmp/evidence
# then screenshot each HTML file at about 1250 px wide, for example with Playwright
```

The HTML is built only from this repository's own outputs and fictional data; it contains no secrets or personal data.
