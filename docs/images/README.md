# Images

**None of these images is a screenshot of n8n, Google Sheets, a terminal or any production system.** No browser or device was available when they were produced, so real interface captures were not possible. Every picture is either a diagram drawn from the real code or export, or a rendering of real command output. Each rendered image carries its own banner saying so, and marks which parts are simulated.

## Diagrams (editable sources in [`../diagrams/`](../diagrams/))

| Image | What it is | Source | Real or proposed |
| --- | --- | --- | --- |
| `architecture-current.png/.svg` | Data flow of v1.1 | `architecture-current.mmd` | Implemented, except the optional proxy (reference code only) |
| `architecture-future.png/.svg` | Where the known limits would be removed | `architecture-future.mmd` | **Proposed, not implemented** (dashed boxes) |
| `workflow-overview.png/.svg` | Node graph of `workflows/leadflow-sales-ai.json` | generated by `scripts/workflow-to-mermaid.js` | Real structure, generated from the export; a test fails if the source is out of date |
| `concurrency-sequence.png/.svg` | Two simultaneous executions and the claim arbitration | `concurrency-sequence.mmd` | The protocol as implemented; verified in simulation only |

Re-render with `npm run docs:diagrams` (needs the Mermaid CLI: `npm install -g @mermaid-js/mermaid-cli`).

## Rendered evidence (generated by `scripts/render-evidence.js`)

| Image | Content | What is real | What is simulated |
| --- | --- | --- | --- |
| `lead-processing.png` | A fictional lead, the HTTP answer and the redacted text the model receives | Validation, redaction, ids, claim | The sheet is in memory |
| `lead-classification.png` | The structured model answer and how it was validated | Schema, quote and figure checks | The model answer is canned (`demo/ai-responses.json`) |
| `lead-scoring.png` | Score breakdown, thresholds, caps | Scoring rules | Inputs are the canned signals |
| `sheets-records.png` | The rows written to `leads` and `claims` with their real columns | Row layout and values produced by the nodes | An in-memory table, not Google Sheets |
| `follow-up-task.png` | Task and draft pending approval | Task and draft generation | In-memory table |
| `demo-summary.png` | Seven fictional leads, twice | Decision code | Model and sheet |
| `error-handling.png` | Broken or hostile model answers and what happens | Validation and error handling | The model answers are injected on purpose |
| `test-suites.png` | Result of each test suite, the build check and lint | Results of the commands at generation time | Suites themselves run against in-memory fakes |
| `security-tests.png` | Titles and results of the security, concurrency and resilience suites | Results | Concurrency is simulated |
| `runtime-verification.png` | The runtime harness locally, and the recorded n8n Cloud result | Local run; the n8n result was recorded during development | n8n execution is no longer inspectable (archived workflow) |

To regenerate them:

```bash
node scripts/render-evidence.js --out /tmp/evidence
# then screenshot each HTML file at about 1250 px wide, for example with Playwright
```

The HTML is built only from this repository's own outputs and fictional data; it contains no secrets or personal data.
